    A small guide to the event loop

    Synchronous code finishes first

    A running JavaScript task completes its synchronous work before queued callbacks run. Calling setTimeout(fn, 0) schedules a timer; it does not interrupt the current function.

    The executor passed to new Promise(executor) runs immediately. Its .then() handlers run later, once the promise is fulfilled.

    Drain the microtask queue

    Promise reactions and queueMicrotask() callbacks use the microtask queue. At a checkpoint the queue is drained, including microtasks added during that checkpoint.

    A nested microtask can therefore run before an already scheduled timer. An endless chain of microtasks can delay other work.

    Await splits a function

    An async function starts synchronously. With an already fulfilled promise, the code after await resumes in a later microtask. The caller continues while the function is suspended.

    Awaiting a pending promise waits for its settlement first. A timer used to settle it adds a task before the continuation.

    Know what this lab measures

    These programs run in a real browser worker. Categories are annotations on log calls, not engine instrumentation. Elapsed times vary with your browser and system load.

    Workers have no DOM or rendering. This lab does not model painting, Node.js phases, process.nextTick(), or ordering across different task sources.
